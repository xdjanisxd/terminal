# Session handoff

The ARM64 native shell smoke investigation disproves a missing reply-draining loop: production and the existing smoke harness both use parse_terminal_output, TerminalState/PendingReplies and typed TerminalReply encoding before queuing PTY writes. The portable-pty Windows backend requests PSEUDOCONSOLE_INHERIT_CURSOR, explaining the initial CSI 6 n; an unanswered cursor query can stall ConPTY startup. The supplied ARM64 output is consistent with that stall but does not prove where it occurs. Mode/title output is not another reply request. No production defect or confirmed ARM64 fix has been established.

The smoke harness now records observed DA/DSR query candidates, generated replies, accepted worker writes, actual session write attempts/results, write failures and process state alongside executable/args/elapsed/marker/visible/raw output. It still uses the production parser and encoder. Three deterministic tests cover split CPR requests, DSR/DA FIFO ordering, continued output/marker parsing, no fabricated responses and queue failure retention. PowerShell still uses deterministic test-only -NoProfile/-NonInteractive commands, verifies the production integration hook and requires the marker plus OSC 7/OSC 133. Production launch policy and the 15-second deadline are unchanged; no architecture exception was added.
