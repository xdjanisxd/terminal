# Current State

## Working

- `terminal-config` owns typed TOML defaults, theme colors, typed command bindings, and validation. The app loads the config at startup and after file content changes, retains the last valid values after an invalid edit, resolves bound keys to commands, executes them in one app dispatcher, and passes theme colors to the renderer. The app command registry also feeds a basic searchable palette opened by Ctrl+Shift+P; palette input stays local, and the renderer draws its text overlay without mutating terminal state. See `docs/CONFIG.md` for the schema and reload boundaries.

- Valid Rust workspace, MIT metadata, and required repository knowledge system
- Cross-platform GitHub Actions gates verified on Windows, Linux, and macOS for x86_64 and ARM64
- Project-owned `terminal-core` models for bounded dimensions, cells with typed single/wide-lead/wide-continuation occupancy, bounded ordered width-zero attachment payloads on printable bases, typed colors and rendition attributes including normal/bold/faint intensity, row-major screen storage, and a grid-owned bounded cursor
- Zero-based checked cell access, default-cell clearing, bounded inclusive region-scroll primitives, and top-left-preserving resize with cursor clamping
- Typed terminal-global modes for cursor visibility, auto-wrap, and insert/replace behavior
- Separate typed input-related state for normal/application cursor keys, focus reporting, bracketed paste, mouse tracking, and mouse encoding
- `TerminalState` owns a viewport selection anchored to the active screen and scroll offset. App pointer events start/extend it when terminal mouse tracking is off or Shift overrides reporting; output, viewport movement, screen changes, and resize clear it. Renderer highlights selected cells; copy extracts projected viewport text, including wide and combining cells, with trailing spaces trimmed per row.
- On Windows, Ctrl+Shift+C copies selection to the Unicode system clipboard through `terminal-platform`, using the app window as clipboard owner. Ctrl+Shift+V reads at most 2 MiB of UTF-16 clipboard data and feeds the existing mode-aware `encode_paste` output to the PTY. Other platforms currently return an unsupported clipboard error.
- OSC 52 accepts only `52;c;<base64>` writes with explicit `AllowWrite` parser policy, valid UTF-8, no NUL, and at most 512 decoded bytes. The app uses `Deny`; queries and other selectors produce no reply or clipboard mutation. The parser's OSC buffer remains fixed at 1024 bytes.
- OSC 8 parses explicit hyperlink spans into bounded terminal-owned target IDs attached to printed cells. Cells retain IDs through scrollback, row edits, and screen switches; viewport lookup resolves only the active screen's visible cells, including wide-cell continuations. Plain URL text is never inferred. Target storage is capped at 1024 entries and reclaims entries no longer referenced by either screen or Primary history when full.
- Ctrl+Shift+left click on a target cell is the only activation gesture. The app command dispatcher accepts only `http://` and `https://` URLs with a nonempty authority and rejects controls, whitespace, backslashes, and userinfo before asking `terminal-platform` to invoke the host URL handler. Terminal output never activates targets on its own, and ordinary click/selection behavior stays separate.
- Parser-independent `TerminalState` owns independent primary/alternate screen buffers selected through typed operations, current rendition, terminal/input modes, bounded tab stops, and a fixed-capacity FIFO of project-owned pending replies for DA1, DA2, ANSI DSR status, and captured ANSI CPR responses
- Controlled state operations for bounded CUU/CUD/CUF/CUB, CNL/CPL, CHA, VPA, CUP/HVP cursor movement; margin-aware SU/SD, IND/RI, and NEL; horizontal tabs and tab-stop mutation; vertical scrolling-margin updates; current rendition; bounded DA1; fixed ANSI DSR status; and absolute ANSI CPR reply generation with FIFO consumption, clearing, resizing, supported mode changes, and a project-owned reset
- Project-owned typed cursor movement and inclusive erase-region operations, with all absolute and relative movement clamped to the active screen
- `TerminalState` owns independent primary and alternate project screen buffers with atomic typed switching; each buffer retains grid/cursor, scrolling margins, delayed-wrap state, and an optional project-owned saved-cursor slot. Primary additionally owns 10,000-row bounded chronological scrollback, retaining exact captured `Cell` rows and evicting oldest first; Alternate has no history. Primary’s viewport is an offset from its live bottom: zero follows normal output, and PageUp/PageDown move by one current terminal height within `0..=history_len`. While a user is scrolled back, each newly captured row advances the offset so existing historical rows remain visible; eviction clamps it to retained history. Capture occurs only for Primary whole-screen upward scrolling (bottom-edge line-feed/IND, NEL, wrapped print, and full-screen SU), never restricted DECSTBM, IL/DL, downward scrolling, editing/erasing, or Alternate. Full reset clears history and returns the viewport to bottom; `?47`, `?1047`, and `?1049` preserve Primary history and its viewport; resize preserves capture-time widths without reflow and clamps its offset. Historical rows narrower than a later resize project default blank cells beyond their captured width. Each saved-cursor slot stores only cursor coordinates plus current rendition; save replaces only the active slot, and restore is an uninitialized-slot no-op that restores only the active slot, clamps coordinates at restore, restores rendition, and cancels delayed wrap. `?47` leaves slots untouched; DEC `?1047` entry resets Alternate including its slot, and its exit selects Primary without restore. DEC `?1049 h` from Primary saves that Primary slot, resets/selects Alternate, and is idempotent while Alternate is already active; `?1049 l` selects Primary and restores its saved slot.
- Parser-independent printable-character, carriage-return, line-feed, index, reverse-index, next-line, bounded cursor-next/previous-line, backspace, horizontal-tab, region-aware-scroll, typed scrolling-margin, and typed rendition operations routed through `TerminalState`
- Delayed right-margin wrapping, auto-wrap suppression, bounded region-aware SU/SD, IND/RI, and NEL scrolling, fixed-screen bottom scrolling, and fixed-width insert/replace output behavior
- Project-owned `terminal-pty` contract plus `PortablePtyBackend`/`PortablePtySession`: native `portable-pty` spawn mapping, raw writer, character-cell resize, explicit/idempotent termination, persisted child-exit polling, and one exclusive project-owned `PtyOutputReader`; arbitrary bytes remain undecoded and output EOF/child exit remain independent. `PtyWorker` adds two deterministic std-only threads: a session/command/lifecycle thread and a blocking-reader thread. It exposes owned raw write, resize, and terminate commands through an eight-slot bounded queue, forwards 1,024-byte maximum raw chunks plus one EOF/Exited event through an eight-slot bounded queue, blocks producers instead of dropping output/lifecycle events, and handles controller/event-receiver disconnects with termination and join. Its optional controller notifier runs only after an event has been queued, retaining transport independence. Lifecycle acceptance passed GitHub Actions run 35329910411 and worker acceptance passed run 35593337297 on all six native runners.
- `terminal-app` starts a local shell for each workspace pane when its native window is created, drains notified raw PTY output on the app event loop through each pane's incremental parser and `TerminalState`, returns queued replies through the associated PTY worker, and resizes each PTY to its split rectangle in terminal cell units. Pending PTY notifications share one proxy wake until the app drains the queues. Output from every visible pane invalidates the frame; hidden tabs continue parsing in the background. Input, selection, clipboard, and viewport navigation target the focused pane. The default workspace retains the former single-terminal behavior. Windows manual acceptance of the original single-terminal path covers PowerShell, basic shell commands, and structurally usable Vim/Neovim rendering.
- `terminal-app` owns a `winit` `ApplicationHandler`, native window lifecycle, coalesced damage-driven redraw dispatch, close handling, DPI/grid synchronization, and renderer wiring. `terminal-renderer` owns synchronous `wgpu` instance/adapter/device/queue setup, a safe native surface, non-zero configuration, resize/reconfiguration, minimize skipping, surface-error recovery, and renderer-owned conversion of the terminal-owned viewport projection into backgrounds, alpha-mask glyph quads, underlines, and cursor primitives. The live cursor is omitted while a viewport is scrolled back. A finite app-owned recovery state arms on restore/fullscreen/surface recovery: the first successful recovery present queues exactly one successor redraw, whose successful present returns the state to idle. Its fixed 1,024×1,024 alpha atlas has 256 deterministic LRU 64×64 slots and reuses the CPU font cache, while unsupported oversize bitmaps are skipped safely. It does not own terminal protocol semantics. GitHub Actions run 35699195505 passed the rendering branch baseline on all six supported runner targets; Windows visual smoke validation confirmed backgrounds, normal/wide/combining glyphs, underline, cursor, resize, minimize/restore, and the finite recovery redraw.
- Without terminal mouse tracking, wheel events stay local to `terminal-app`: line deltas move three rows per line, pixel deltas use the current cell height with fractional remainder, and only Primary history is passed to `TerminalState::scroll_viewport_rows`. With tracking, wheel movement emits terminal mouse reports through the PTY and does not move the viewport. The core clamps local movement to `0..=history_len`; offset zero follows the live bottom, while newly captured output preserves the historical viewport when scrolled back. Alternate screen ignores local wheel navigation. The renderer reads only Primary history length, visible row count, and viewport offset, then derives a right-edge track/thumb overlay in surface pixels; it never mutates terminal state. The scrollbar is hidden with no history or on Alternate. Its thumb reaches the bottom at offset zero, moves upward for older rows, and recomputes after history growth and resize. Thumb dragging is not implemented.
- `terminal-renderer` owns initial terminal-font discovery/loading through `fontdb`: it retains the selected face and source database and can require a named monospace family through project-owned `FontRequest`. On Linux, the default request resolves the system's `monospace` match through `fc-match`, loading the resolved file into `fontdb` if its directory scan missed it; if that match is unavailable or unusable, it selects a loadable discovered monospace face. Other platforms keep the `fontdb` generic-family query. Missing or proportional named faces fail renderer initialization clearly. It uses `swash` behind project-owned shaped-glyph and CPU alpha-bitmap results to shape text and rasterize glyphs. When the primary face cannot map a scalar, it uses the first matching metadata-sorted discovered fallback face and memoizes that choice. Shaped strings have a bounded 512-entry cache cleared on font-scale changes; raster bitmaps use a renderer-owned 256-entry LRU keyed by face, glyph ID, and pixels-per-em. The renderer checks the atlas before CPU rasterization and writes only changed contiguous instance-buffer spans, while each submitted frame still projects the full visible viewport and regenerates its CPU instances.
- Incremental project-owned `TerminalParser` adapter encapsulating `vte` and preserving parser state across input chunks
- Deterministic repository-owned compatibility fixtures validate the supported slice against representative shell prompt redraw, full-screen editor alternate-screen, and multiplexer control/output flows; deferred OSC title traffic is a non-corrupting no-op.
- Parser routing for printable input, CR, LF, BS, HT, HTS, IND, RI, NEL, primary DA1 queries `CSI c`/`CSI 0 c`, ANSI DSR status `CSI 5 n` and cursor-position `CSI 6 n` queries, TBC, CUU/CUD/CUF/CUB, CNL/CPL, CUP/HVP, CHA/VPA, bounded current-row ICH/DCH/ECH, ED, EL, cursor-relative IL/DL, region-aware SU/SD, DECSTBM, non-clearing DEC private alternate-screen mode 47 switching, clearing/resetting DEC private alternate-screen mode 1047 entry/primary selection exit, saved-primary/resetting-Alternate/restoring-Primary DEC private mode 1049, IRM, private DECCKM/DECAWM/DECTCEM, and SGR reset, bold, faint, italic, underline, inverse, defaults, ANSI 16 colors, semicolon-form indexed foreground/background colors, and semicolon-form exact RGB foreground/background colors; unsupported parser actions and parameters are ignored without approximation
- IL/DL `CSI Ps L`/`CSI Ps M` use the cursor-to-bottom portion of the active scrolling region, leaving rows above the cursor and outside margins unchanged; blank lines use canonical default cells and delayed wrap is preserved

The app reports clicks, releases, motion, and wheel while mouse tracking is active; otherwise wheel scrolling stays local to Primary history. No clipboard paste source is wired yet.

## Partial

- `terminal-workspace` owns typed tab, pane, session, and recursive horizontal/vertical split layout models. A typed TOML definition recreates tab order, titles, split structure, initial focus, and one fresh local shell per pane at startup; it does not restore live processes or terminal contents. The app commands create, focus, and close tabs/panes through the central dispatcher. The split tree tiles the active tab's viewport into pane rectangles, dividing each node evenly and assigning odd pixels to its second child. The renderer draws every visible pane inside its rectangle, marks the focused pane with a border, and shows its cursor alone. Focused pane state and session transport remain separate, and the window title reports focus. Workspace hot reload is deferred.

- `TerminalState::reset` restores the screen model to initial state at existing dimensions, including full-screen vertical margins, while preserving already-generated pending replies; it is explicitly not DECSTR or RIS
- `Cell` stores one Unicode scalar, its rendition snapshot, and up to eight ordered width-zero scalars in a single or wide-leading cell; a distinct continuation cell stores no duplicate character, rendition, or combining payload. Width-zero output attaches only to the preceding logical printable base without moving the cursor or resolving delayed wrap; without a base it is ignored, and overflow returns `PrintError::CombiningMarkOverflow` without mutation. Grid mutation normalizes every row so each lead is immediately followed by one continuation and continuations never stand alone; grapheme segmentation, normalization, ZWJ handling, and renderer shaping remain deferred.
- Printable output supports width-one and width-two Unicode scalars through the project-owned `CellOccupancy` model and `unicode-width`; width-zero classification uses the narrow attachment policy above rather than claiming full Unicode grapheme correctness, while malformed UTF-8 replacement characters remain errors
- Faint is represented in terminal state and captured by cells, but visual dimming remains deferred with renderer implementation
- The parser recognizes broader VTE syntax incrementally, but only printable input, CR, LF, BS, HT, HTS, IND, RI, NEL, primary DA1, ANSI DSR cursor-position queries, the supported cursor/erase/region-aware-scroll/DECSTBM CSI subset, IRM/DECAWM/DECTCEM, and the documented style, default, ANSI 16-color, semicolon-form indexed-color, and semicolon-form truecolor SGR subsets currently have terminal semantics
- Resize preserves the top-left rectangular intersection of both screen-local grids, resets each screen-local margin to the full new height, cancels delayed wrap, preserves valid shared tab stops and global rendition/modes, clamps active/saved cursor restoration safely, retains Primary history at capture-time widths with no text or history reflow, and clamps its viewport offset to the retained history length.
- Public branding and minimum operating-system versions remain intentionally deferred as documented in ADR-0008

## Missing

- Remaining CSI/SGR style semantics and modes, colon-form color semantics, OSC/DCS semantics, secondary/tertiary DA replies, other DSR/CPR forms, origin mode, and additional alternate-screen semantics
- Clipboard support outside Windows, expanded command palette features, workspace, and broader PTY/application integration behavior remain deferred
- Compatibility/performance baselines; the interactive frame-pacing pass reduced repeated instance uploads and eliminated stale-size surface configuration during live resize. Manual Windows traces still show full-visible-grid projection and CPU instance generation on every present, and PowerShell can produce multiple presents for one key through separate PTY chunks. Damage-aware CPU updates, proof-based suppression of redundant presents, and measured input-to-present latency remain performance debt (see `docs/PERFORMANCE.md`).
