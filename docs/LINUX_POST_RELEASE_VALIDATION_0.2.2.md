```sh

extracted/terminal -V
ldd extracted/terminal
```

- **Release blocker: blocked-write close hangs.** `python3 /tmp/terminal-v022-post-release/blocked_writer_diagnostics.py` ran the downloaded binary with an isolated HOME/XDG environment and a raw-mode child that emitted cursor-position requests without reading responses. The parent inspected the live writer's `poll` arguments via `/proc/<pid>/task/<tid>/syscall` and `/proc/<pid>/mem`: the second descriptor requested `POLLOUT`, had no readiness events, and resolved to `/dev/ptmx`; the first descriptor was the cancellation wait. After KDE requested window closure, the application diagnostic log recorded `app event=close-requested`, but the process did not exit within 15 seconds. The harness forcibly killed it. This reproduced two earlier 15-second timeouts, including one with the child paused after the blocked-write observation; the diagnostic run used an unpaused child. Evidence: `/tmp/terminal-v022-post-release/blocked-writer-diagnostics/`. An exact copy of the executed harness is preserved at [blocked_writer_diagnostics.py](measurements/linux-post-release-0.2.2/blocked_writer_diagnostics.py), SHA-256 `7c64d26b5a86a0170352f5b2e4a48657c8084d2e0c6de76838eeeae54c156a26`. It uses fixed temporary paths and is preserved for inspection; a fresh isolated path is required before rerunning it. Downloaded executable SHA-256: `e96f0d77c79e96b27fd8955de078449e71e799513909e1726863271e31803aa7`. The observed poll descriptor tuple was `(42, 1, 0, 37, 4, 0)` with fd 37 resolving to `/dev/ptmx`; the diagnostic logged `app event=close-requested` before the 15-second timeout. The shutdown hang is confirmed for this workload. Tagged-source inspection identifies the likely cause: `ShellSession` implements `PtySession` but does not forward `take_io_cancellation`, so it inherits the trait default `None`. `PtyWorker::start_with_notifier` takes that capability from the wrapper; consequently shutdown cannot wake the backend writer through cancellation before sending termination and joining. This matches the observed blocked writer and close hang; a separately reviewed fix and an application-wrapper regression test are needed to establish the fix. Broader triggers remain unverified. No production fix was attempted.
